〇、软件一句话定位

桌面轻提醒：一个安静地浮在桌面上、用「清晰 → 半透明 → 图标」自动收起、能自动记住你正在做什么并到点提醒你的多线程工作小助手。原则：平时不打扰，需要时就在眼前。

一、技术定案（已确认，不再变更）

决策项定案说明
技术选型C# + WPF（方案 B）Windows 原生框架；便携版体积目标 2~8MB；毛玻璃/亚克力系统原生支持
默认任务时长5 分钟可在设置中修改
系统兼容Win10 / Win11 必须；Win7 尽力兼容不牺牲 Win10/11 体验去兼容 Win7
发布形式便携版（解压即用）不强制安装包；后续需要再加

界面语言仅中文国际化后续版本再考虑
多显示器无特殊逻辑图标/窗口通过拖动自行摆放，位置记忆

R1.8P0到期任务不自动标记（追问确认）：进入「过期」状态红色显示，直到你手动处理（完成/稍后/删除）

R1.11P0稍后提醒：任务条目后的「稍后」按钮，固定选项 5/10/15/30 分钟；选择后从现在起重新计时（追问确认）
R1.12P0已完成列表：不在主界面直接出现，通过标题栏「✓」按钮进入单独区域/界面
R1.13P0已完成任务操作：「恢复」（误点可找回）和「删除」（永久移除）；删除时弹确认框（追问确认）
R1.14P0空状态：显示三行空列表，第一行浅色字提示「双击新建任务」
R1.15P1任务数据持久化：重启软件后任务、已完成、设置全部保留
R1.16P2任务列表排序：按到期时间升序（追问确认），最早到期的在最上面

三、架构设计（确保「改一处不影响其他」）

3.1 四层架构（依赖只许从上往下）

层级模块职责（只做这些，不做别的）
表现层 UI主面板、对话框、图标窗口、托盘只负责「画出来」和「收点击」；不写任何业务判断；颜色只从主题管理器取
应用层状态机、任务调度、提醒器管理 ACTIVE/GLASS/ICON 切换、计时、到期提醒；不关心窗口怎么画
领域层TaskManager、配置管理任务的增删改查、到期计算、配置读写；纯逻辑不依赖界面库，可单独测试
基础设施Windows 封装、持久化、日志所有系统 API（窗口识别、原生消息、注册表）集中于此；出问题只改这一层
为什么能避免「改 A 坏 B」：每一层只允许调用它下面那一层（MVVM 框架天然支持）。UI 改样式不影响逻辑；逻辑改算法不影响界面；系统层换实现不影响业务。任何跨层调用都是架构违规，评审时打回。

3.2 三个最容易出问题的点，架构级解决

老问题架构方案为什么这次不会再犯
窗口拖拽/调大小反复失灵窗口级交互（拖拽、右下角调大小）统一走 WM_NCHITTEST 原生消息；按钮/列表点击走组件事件系统级处理不被子控件拦截，机制唯一、入口唯一
主题只变背景不变字体ThemeManager 唯一主题源；所有控件实现 ApplyTheme()；切换时递归刷新整个控件树新控件漏实现 ApplyTheme 在测试期即被发现
异常静默、点不动没反应全局异常捕获写入日志文件；每次操作有日志可查任何问题都能看日志定位，不再「猜」

3.3 状态机（软件核心心脏）

ACTIVE 清晰→ 无操作 5 分钟→ GLASS 半透明→ 30 秒无操作→ ICON 图标
鼠标悬停 GLASS→ACTIVE 点击 ICON→ACTIVE ICON 定期提醒→GLASS 过期任务每 5 分钟→GLASS 提醒

状态机由应用层独立模块管理，UI 只响应状态变化指令，不自己改状态。

四、开发与验证流程（防止重蹈覆辙）

需求冻结（本文档）→ 架构与接口定义→ 领域层开发+单测→ 应用层开发+单测→ UI 层开发→ 冒烟测试→ 打标签发布
  • 一次只改一件事：每个修改项独立提交，提交信息写明改了什么、为什么
  • 每完成一个模块打一个版本标签：v0.1（任务管理）→ v0.2（状态机）→ … 每个标签都有可运行版本，随时回退
  • 修改必须过三关：单元测试 → 冒烟测试 → 你的人工验收，三关全过才合入
  • 每个「好用」版本：立即打标签 + 备份 exe，永远能退回去
持续需求与问题清单：后续你用「先记录再改」提出的任何需求，都登记到 GitHub Issues + 本文档附录二，随时可查状态。
